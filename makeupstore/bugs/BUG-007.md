# BUG-007 — Riesgo de XSS: los datos del catálogo se insertaban en la página sin sanitizar

| Campo | Valor |
|---|---|
| **Módulo** | M2 Catálogo / Panel de administración / API |
| **Tipo** | Seguridad (Cross-Site Scripting) |
| **Severidad** | Crítica |
| **Prioridad** | Alta |
| **Entorno** | Todos |
| **Estado** | ✅ Verificado |
| **Commit de corrección** | `40c53c4` |

## Descripción
El texto del catálogo (nombres, descripciones) se insertaba en el HTML sin limpiarlo, y había JavaScript en línea (`onclick`, `onerror`). Un dato malicioso guardado en el catálogo podía ejecutar código en el navegador de los clientes.

## Pasos para reproducir (entorno de prueba)
1. Guardar un producto cuyo nombre contenga una etiqueta HTML con un evento (ej. una imagen con `onerror`).
2. Abrir el catálogo.

## Resultado esperado
El texto se muestra como texto plano y el servidor rechaza datos inválidos.

## Resultado obtenido
El contenido se interpretaba como HTML y el evento podía ejecutarse.

## Causa raíz
Uso de inserción de HTML sin escapar, ausencia de validación del catálogo en el servidor y JavaScript en línea.

## Corrección aplicada
- `api/_lib/catalog-schema.js`: valida todo el catálogo antes de guardarlo y **rechaza datos inválidos con error 400**.
- Escape de todo el texto antes de mostrarlo.
- Eliminación del JavaScript en línea.
- **Content Security Policy (CSP)** en `vercel.json` que bloquea scripts no autorizados.

## Verificación
- [x] Un nombre con HTML se muestra como texto.
- [x] La API rechaza un catálogo inválido con 400.
- [x] La CSP bloquea scripts en línea.
