# BUG-002 — Credencial del panel de administración expuesta en el código del cliente

| Campo | Valor |
|---|---|
| **Módulo** | Panel de administración |
| **Tipo** | Seguridad (exposición de credenciales) |
| **Severidad** | Crítica |
| **Prioridad** | Alta |
| **Entorno** | Cualquier navegador (código fuente público) |
| **Estado** | ✅ Verificado |
| **Commit de corrección** | `cebf103` |

## Descripción
Existía una contraseña por defecto y `admin.js` permitía un acceso "sin conexión" con una clave escrita en el código JavaScript. Cualquier persona podía verla desde las herramientas del navegador y obtener acceso al panel para modificar precios y productos.

> La credencial no se reproduce en este reporte por buenas prácticas de seguridad.

## Pasos para reproducir
1. Abrir el panel de administración.
2. Abrir DevTools → Sources → `admin.js`.
3. Buscar la lógica de autenticación.

## Resultado esperado
Ninguna credencial existe en el código del cliente. La autenticación se valida solo en el servidor.

## Resultado obtenido
La clave era visible en texto plano y existía una clave por defecto.

## Causa raíz
Se implementó un acceso de respaldo en el cliente y un valor por defecto para facilitar el desarrollo.

## Corrección aplicada
- Se eliminaron la clave por defecto y el acceso sin conexión.
- `api/catalog.js` exige la variable de entorno `ADMIN_PASSWORD`. Si no está configurada, **rechaza el acceso con error 500** en vez de permitirlo (*fail closed*).
- En desarrollo local, la clave se lee desde `.env.local`, que no se versiona.

## Verificación
- [x] Búsqueda en todo el código del cliente: no hay credenciales.
- [x] Sin `ADMIN_PASSWORD` configurada, la API responde 500 y no permite el acceso.
- [x] Con la clave correcta, el acceso funciona solo vía servidor.

## Recomendación
Rotar la contraseña, ya que la anterior estuvo expuesta.
