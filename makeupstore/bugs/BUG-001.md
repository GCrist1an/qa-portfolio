# BUG-001 — La tienda no responde en redes móviles lentas mientras carga el catálogo

| Campo | Valor |
|---|---|
| **Módulo** | M1 Inicio / M2 Catálogo |
| **Tipo** | Rendimiento / Usabilidad |
| **Severidad** | Alta |
| **Prioridad** | Alta |
| **Entorno** | Celular Android/iOS, red 4G lenta |
| **Estado** | ✅ Verificado |
| **Commit de corrección** | `b45a139` |

## Descripción
En conexiones lentas, los botones principales (Ver catálogo, carrito y búsqueda) no respondían hasta terminar la descarga completa del catálogo (~600 productos). El usuario percibía la tienda como "pegada".

## Pasos para reproducir
1. Abrir DevTools → Network → limitar a "Slow 4G".
2. Cargar la página de inicio.
3. Tocar "Ver catálogo", el carrito o la búsqueda antes de que termine la carga.

## Resultado esperado
Los controles responden de inmediato y el usuario ve un indicador de carga.

## Resultado obtenido
Los controles no responden hasta que el catálogo termina de descargarse. No hay retroalimentación visual ni manejo de error de red.

## Causa raíz
La inicialización de los eventos de la interfaz dependía de que el catálogo estuviera descargado.

## Corrección aplicada
En `public/js/app.js`, los controles se habilitan primero y el catálogo se descarga después. Se muestra "Cargando productos…" y, si la red falla, un botón **Reintentar**.

## Verificación
- [x] Con "Slow 4G", los botones responden al instante.
- [x] Se muestra el mensaje de carga.
- [x] Con la red desconectada aparece "Reintentar" y recupera la carga al reconectar.
