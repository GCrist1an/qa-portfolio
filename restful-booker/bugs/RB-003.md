# RB-003 — Se acepta una reserva con precio total negativo

| Campo | Valor |
|---|---|
| **Módulo** | Reservas — `POST /booking` |
| **Tipo** | Funcional / Datos |
| **Severidad** | Alta |
| **Prioridad** | Media |
| **Entorno** | Newman (CLI) · https://restful-booker.herokuapp.com · ejecución 2026-11-07 |
| **Estado** | Nuevo |
| **Commit de corrección** | — |

## Descripción
La API acepta `totalprice` negativo y crea la reserva. Un precio negativo puede generar saldos a favor del cliente o descuadres contables.

## Pasos para reproducir
1. Enviar `POST /booking` con este cuerpo:
   ```json
   {
     "firstname": "Cristian", "lastname": "QA", "totalprice": -100, "depositpaid": true,
     "bookingdates": { "checkin": "2026-12-01", "checkout": "2026-12-05" },
     "additionalneeds": "Breakfast"
   }
   ```
2. Revisar la respuesta.

## Resultado esperado
`400 Bad Request` indicando que `totalprice` debe ser mayor o igual a 0.

## Resultado obtenido
`200 OK` y la reserva se crea (devuelve un `bookingid` nuevo) con `totalprice: -100`.

## Causa raíz
Sin determinar. No se valida el rango de `totalprice`. No aplica: la API es de terceros y no tenemos acceso al código. Queda reportado para el equipo responsable.

## Corrección aplicada
No aplica: la API es de terceros y no tenemos acceso al código. Queda reportado para el equipo responsable.
