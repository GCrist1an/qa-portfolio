# OBS-002 — Eliminar una reserva responde 201 Created en lugar de 204

| Campo | Valor |
|---|---|
| **Módulo** | Reservas — `DELETE /booking/:id` |
| **Tipo** | Diseño de API |
| **Severidad** | Sugerencia |
| **Prioridad** | Baja |
| **Entorno** | Newman (CLI) · https://restful-booker.herokuapp.com · ejecución 2026-11-07 |
| **Estado** | Nuevo |
| **Commit de corrección** | — |

## Descripción
Una eliminación exitosa responde `201 Created` con el cuerpo `Created`. Es lo que dice la [documentación oficial](https://restful-booker.herokuapp.com/apidoc/index.html), así que **no es un defecto funcional**. Sin embargo, 201 indica que se creó un recurso, lo contrario de lo que hace la operación.

## Pasos para reproducir
1. Obtener un token con `POST /auth` y crear una reserva.
2. Enviar `DELETE /booking/{id}` con `Cookie: token=<token>`.

## Resultado esperado (recomendación)
`204 No Content` (o `200 OK` si se devuelve un cuerpo).

## Resultado obtenido
`201 Created`, cuerpo `Created`. La eliminación sí ocurre: API-011 confirma un 404 al consultar la reserva después.

## Causa raíz
Decisión de diseño documentada de la API.

## Corrección aplicada
En la colección, la aserción de API-010 ahora valida 201, como dice la documentación. La recomendación REST queda registrada en esta observación.

## Verificación
- [x] API-010 pasa con la aserción alineada a la documentación.
